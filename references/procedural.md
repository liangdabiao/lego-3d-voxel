# 程序化生成体素：没有模型文件时怎么办

这份文档记录一次完整实战（体素风参考图 → 430 件成品），每个数字都是实测的。
不是"通用最佳实践"，而是"这条路走过一遍，哪里会摔"。

## 一、先判断该不该走这条路

| 手上有什么 | 做法 |
|---|---|
| `.glb` / `.gltf` | 切片（`vox.py`），形体忠实度最高 |
| **体素风 / 像素风的参考图**（块面清楚、色块分明） | **程序化生成**（`gen.py` + 场景文件） |
| 写实照片 | 两条都不成立。本项目实测过照片取色，"形状失真 + 颜色全错"，用户明确否决 |
| 体素风参考图，但只有一张小图 | 仍可生成，但要先跟用户对齐"大概多少格"——格数决定细节上限 |

参考图本身就是体素化的，说明它的作者已经在格子上做过造型决策（哪里 1 格、哪里 3 格）。
照着这些块面写基本形，比找模型切片更准，而且能直接控制"件数"和"格数"。

## 二、五步流程

```bash
# 1. 写场景文件（build(v)，用基本形拼）
#    examples/whale-island.py 是最小完整例子，直接改它最快

# 2. 生成体素
python <skill>/scripts/gen.py --scene <work>/scene.py --out <work>/volume.json

# 3. 看三视图 + 分层图：只能查轮廓、朝向、穿模，查不出"像不像"
python <skill>/scripts/preview.py --vol <work>/volume.json --outdir <work> --px 8

# 4. 装配 + 渲染成品图，**看渲染图**（这一步不能省，见第四节）
# 5. 改一个参数 → 回到第 2 步
```

一个循环的耗时（1,265 格的小件）：生成 < 1 秒，装配 + 渲染 quick.png 约 30~60 秒。
所以这条路能承受十次以上的迭代，别指望一次成型。

## 三、基本形怎么选

| 形体 | 用什么 | 备注 |
|---|---|---|
| 主体体积（身体、头） | `v.ellipsoid(cx,cy,cz,rx,ry,rz,c)` | 先定三个半径，再拧一个 |
| 需要特征截面（方头、扁嘴） | 手写 `inside_ellipsoid` 变体，或在椭球外再叠一个截面渐变的柱 | 鲸鱼的方头就是这么来的：x 区间内 ry/rz 随 t 线性放大 |
| 底座 / 浮岛 / 树干 | `v.revolve(cx,cz,radii,top_y,color)` | radii 是**由上往下**的半径剖面；`color` 回调能拿到 `d`（到轴心距离）分层上色 |
| 尾巴 / 四肢 / 斜向细长体 | `v.tube(path, radius, c)` | radius=0 是逐格线，1 是菱形截面。**细到 1 格会在渲染里断** |
| 眼睛、小件、单点 | `v.put(x,y,z,c)` | 1 格黑 + 1 格白就够；放大到 2×2 会变成卡通眼 |
| 换色不改几何（肚皮、背脊阴影） | `v.repaint(pred, c, only={'Blue'})` | 用 `only` 限定原色，避免把眼睛也刷成肚皮色 |
| 杂色（草皮、岩层） | `v_hash(x,y,z,salt)` 阈值分流 | 确定性伪随机，同一格永远同色，改参数重跑才不会整体抖动 |

## 四、最贵的一课：形体问题必须看渲染图

**正视图/ASCII 图上"看起来对"的形体，在 3D 渲染里经常是错的。** 实测踩过的三处：

1. 鲸鱼"陷进岛里"——正视图上岛面沿是齐的，看不出鲸鱼和草皮在同一层；渲染图上能一眼看出前半身埋在草里。
2. 棕榈树被鲸身整个挡住——坐标算下来在岛的侧面（+x），正视图里它明明"在画面右侧"；渲染图里根本看不见。
3. 尾鳍"两撮竖立的尖角"——正视图是两个小方块，看着像尾鳍；渲染图里是两根短叉，完全没有鲸尾的形态。

结论：**每改一版都要出 quick.png 看**，不要用 ASCII 图代替验收。这条是时间花得最值的。

## 五、实测迭代日志（蓝鲸浮岛，8 版）

| 版 | 现象 | 改了什么 | 结果 |
|---|---|---|---|
| 1 | 鲸鱼陷进岛里、肚皮太小、眼睛太大、尾巴和棕榈粘一起 | 岛半径收小、`BODY_CY` 抬高、肚皮椭圆放大、眼睛改 1 格 | 脱离草皮，但浮空偏高 |
| 2 | 鲸鱼浮在岛上方 | `BODY_CY` 7.2 → 6.3，岛半径 5.9 → 6.1 | 坐稳，"坐"的感觉对了 |
| 3 | 尾鳍像两根短叉 | 尾鳍改成同一层横向张开的 V，茎加粗到 3 格 | 尾巴成形 |
| 4 | 背部一片花点 | 背脊暗蓝阈值 0.55 → 0.85（只留极少量） | 背部干净 |
| 5 | 棕榈树在画面里消失 | 从 +x 侧挪到右前角（x≈5,z≈4） | 能看见，且不挡肚皮 |
| 6 | 棕榈像一丛灌木 | 叶尖下垂一格 + 四角补浅绿 + 树顶加一格 | 能认出是棕榈 |

被推翻的做法（别再试）：

- 靠"多加几个色"来补体积：会把主体打花，宁可只用 Blue + Tan 两色 + 极少量 Medium Blue。
- 靠"把岛做大"让鲸鱼显得居中：岛一大，鲸鱼就小，构图散。
- 靠"把尾巴做细"显得轻巧：1 格宽的斜向体在渲染里会断成几截。

## 六、这类模型的已知代价（交付时必须主动说）

- **件数 ≈ 体素数 × 1/3**：每格一颗 1×1×3 砖，同色同层相邻会并成整条。
  实测 1,265 格 → 430 件、19 × 22 × 16 格。
- **未连接 33 处**：1 格厚的悬挑（棕榈叶尖、胸鳍、灯笼）下方没有同色砖承托，是"一格一砖"的固有问题。
- **色带边界是阶梯状**：椭圆/谓词生成的颜色边界必然出现锯齿，多混一格浅色消不掉，
  只能在更高分辨率下才变平滑（而更高分辨率 = 更多件数）。
- **左右对称靠手写**：`for side in (-1, 1)` 里写错一侧，正视图看不出来，要在渲染图上两侧对比。

## 七、交付前自查

- [ ] 主体真的"坐"在底座上，没有陷进去 / 浮起来
- [ ] 每个附件（树、灯、鳍）在渲染图里都看得见，没有被主体挡掉
- [ ] 1 格厚的悬挑在渲染图里没有断开
- [ ] 色块成片，没有大面积散点（尤其背脊、岩层这类"加暗色做体积"的地方）
- [ ] 件数与格数、未连接数都报给用户，不藏
